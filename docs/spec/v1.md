# Spec v1

## Goals
The user's original request, verbatim: "build 1". It picks option 1 from the previous turn: wire the back end into the team's own pages. After the PR merges, a teammate runs `git pull`, starts the server, and sign-in, Save and history all work.

Terms used in this spec:
- **The drop-in:** `static-site/inspection-backend.mjs`, `static-site/inspection-backend-core.mjs` and `static-site/supabase-config.js`.
- **The dashboard:** `static-site/index.html`, served at `http://localhost:5500/`.
- **Jarvis:** the build assistant that wrote this spec and makes the delegated choices.

Goals:
- After a `git pull`, an inspector whose Google account is on the project's Google test-user list (A15) can do the whole flow:
  - start the server with `python3 -m http.server 5500` in `static-site/` and open `http://localhost:5500/`
  - sign in with Google
  - pass the ArcGIS check
  - select a BMP
  - save an inspection that the database confirms
  - see that inspection again after a reload
- No teammate has to copy or paste code to get there.
- Saves work on the BMP layer the map actually shows: `UMBC_BMP_ArcGIS_Import`, item `5d70e438bb6045d6b3af05aee061e3cd`, layer 0 (A1).
- Nothing typed into the inspection form is silently lost on Save.

## Non-goals
- **No photos, "Needs verification" outcome, email, PDF export or offline use.** Source: docs/designs/inspection-database-and-umbc-sign-in.md:53; app/docs/superpowers/specs/2026-10-26-bmp-inspection-demo-design.md:9.
- **No BMP data without an ArcGIS sign-in.**
  - The layer is shared only with the "Stormwater ArcGIS Map" group (A1).
  - Changing sharing is ruled out (CLAUDE.md "Planned app"; RECON.md:39).
  - A later version can copy the BMPs into the database so workers need only Google.
- **No publishing of the Google consent screen.** The Google app stays in Testing mode (A15).
- **No email + password form on any page.** Source: D3, intake Q3.
- **No edits to ArcGIS data.** The map stays read-only (CLAUDE.md).
- **No ArcGIS sign-out.** "Sign out" ends only the Supabase session.
- **No fixes to `static-site/test-facility.mjs` or `static-site/test-selection.mjs`.** They already fail before this work (A17).
- **No display of inspections saved against the old layer** (item `cc6a7a27…`, layer 3). They stay in the database unchanged (A3).
- **No browser automation that signs in with a real Google or ArcGIS account.** Browser criteria are checked by hand (A19).
- **No Next.js app.** `app/` stays a placeholder (CLAUDE.md).

## User stories
- **S1 (P1):** As a UMBC inspector, I want one sign-in path (Google `@umbc.edu`, then the ArcGIS check, then the dashboard), so only signed-in `@umbc.edu` accounts reach the dashboard and my saves are tied to me.
- **S2 (P1):** As a signed-in inspector, I want to save an inspection for the BMP I selected, so the record is stored only after the database confirms it, and a retry never makes a duplicate or drops an edit.
- **S3 (P1):** As a signed-in inspector, I want to see my own past inspections of the selected BMP and open one to see what I saved, so I can check my work after a reload.

## Acceptance criteria
- **AC1 (S1):** WHEN a visitor with no Supabase session opens `http://localhost:5500/` THE SYSTEM SHALL redirect to `login.html` before the ArcGIS sign-in redirect starts and before any dashboard content is shown, while the static "Verifying your ArcGIS session" gate may show during that check.
- **AC29 (S1):** WHEN the Supabase session's email does not end in `@umbc.edu` THE SYSTEM SHALL end that session, go to `login.html` and show "Only @umbc.edu accounts can use this app.", passing that message through sessionStorage, not the URL.
- **AC33 (S1):** WHEN the sign-in code (the drop-in or supabase-js from its CDN) fails to load, or `supabase-config.js` is missing, THE SYSTEM SHALL show "Sign-in could not load. Check your connection and reload." on `login.html` and on the dashboard's sign-in gate instead of a page that never finishes loading.
- **AC2 (S1):** WHEN `login.html` loads THE SYSTEM SHALL show a single "Sign in with Google" button, no email or password fields, and no text describing a demo or test password.
- **AC3 (S1):** WHEN the inspector presses "Sign in with Google" THE SYSTEM SHALL send the browser to Google with `login.html` as the return address, or show the drop-in's "Could not open Google sign-in" message and re-enable the button if that fails.
- **AC4 (S1):** WHEN `login.html` loads with `code` in its URL and finishing the sign-in yields a `@umbc.edu` session THE SYSTEM SHALL show "Finishing sign-in…" with the button disabled while it works, then set the ArcGIS sign-in intent flag that `map.js` reads (sessionStorage key `umbc-stormwater.arcgis.signin` = `"1"`), then go to `./` (`http://localhost:5500/`, the registered ArcGIS redirect URL), where `map.js`'s ArcGIS gate runs.
- **AC5 (S1):** WHEN `login.html` loads with `error` or `error_description` in its URL THE SYSTEM SHALL show the error text and stay on `login.html` without continuing, even if an earlier session exists, showing the AC6 controls when a session exists and the Google button otherwise.
- **AC35 (S1):** WHEN `login.html` loads with `code` in its URL but finishing the sign-in yields no session and no error THE SYSTEM SHALL show "Sign-in did not complete. Try again." and stay on `login.html`.
- **AC6 (S1):** WHEN `login.html` loads with none of `code`, `error` or `error_description` in its URL while a `@umbc.edu` session exists THE SYSTEM SHALL show the signed-in email, a "Continue" button that sets the intent flag and goes to `./`, and a "Sign out" button, with the Google button hidden.
- **AC7 (S1):** WHEN the ArcGIS check on the dashboard succeeds THE SYSTEM SHALL show the signed-in email and a "Sign out" button in the top bar.
- **AC8 (S1):** WHEN the inspector presses "Sign out" (top bar or `login.html`) THE SYSTEM SHALL end the Supabase session and show `login.html` with the Google button.
- **AC36 (S1):** WHEN the Supabase session ends or expires (in this tab or another) THE SYSTEM SHALL show "Signed out" in place of the email in the top bar and stay on the dashboard keeping every form value, and show the email again once a sign-in happens in another tab.
- **AC9 (S1):** WHEN the dashboard loads with an ArcGIS `?code=` in its address THE SYSTEM SHALL leave that code to ArcGIS and never pass it to Supabase, because only pages listed in `signInPages` read `?code=` for Supabase.
- **AC10 (S2):** WHEN the inspection form is shown and no save is in flight THE SYSTEM SHALL offer only Pass and Fail as results, have no photos input, show an enabled "Save inspection" button in place of "Submit inspection · coming later", and contain none of the texts "Inspection entries are not saved or submitted", "Preview controls only" or "No inspection data is submitted".
- **AC37 (S2):** WHEN no save is pending and the inspector presses "Clear inspection & restore fields" THE SYSTEM SHALL clear the type, the result and the observations without a script error.
- **AC11 (S2):** WHEN the migration in A2 is applied and an inspector has selected a BMP from item `5d70e438bb6045d6b3af05aee061e3cd` layer 0, chosen an inspection type and a result, and pressed "Save inspection" THE SYSTEM SHALL show "Saved at <time>" only after `create_inspection` returns a record ID, with no other form field required.
- **AC12 (S2):** WHEN a save request is in flight THE SYSTEM SHALL disable "Save inspection", the eight fields locked in AC31, "Restore editable fields" and "Clear inspection & restore fields", show "Saving…", and send at most one request.
- **AC30 (S2):** WHEN a save request is in flight THE SYSTEM SHALL ignore map clicks and disable the BMP dropdown until the request finishes.
- **AC13 (S2):** WHEN a save gets no reply (network failure) THE SYSTEM SHALL show the "not confirmed" message and keep the same draft ID, so pressing "Save inspection" again creates at most one database record.
- **AC31 (S2):** WHEN a save is not confirmed THE SYSTEM SHALL set `disabled` on the inspection type, the result, the observations and the five form fields of AC18, and on "Restore editable fields" and "Clear inspection & restore fields", until a later Save is confirmed or a different BMP is selected.
- **AC38 (S2):** WHEN a save is not confirmed and the same BMP is selected again by map click or by dropdown, or a late address lookup finishes, THE SYSTEM SHALL leave the type, the result, the observations and the five form fields of AC18 unchanged.
- **AC14 (S2):** WHEN a save is confirmed (the drop-in returns ok: "Saved at …", "Already saved …" or "Your earlier save did go through …") THE SYSTEM SHALL show that message, clear the inspection type, the result and the observations, re-enable every field, start a new draft for the same BMP, and refresh that BMP's history.
- **AC15 (S2):** WHEN the same BMP is selected again before a confirmed save THE SYSTEM SHALL keep the current draft ID, where "same BMP" means the same item, layer and object ID as the drop-in's `featureRef`, and facility-ui uses that same identity to decide whether to keep form values.
- **AC16 (S2):** WHEN a different BMP is selected THE SYSTEM SHALL start a new draft and clear the type, the result, the observations and the verified location.
- **AC17 (S2):** WHEN the selected feature is not from item `5d70e438bb6045d6b3af05aee061e3cd` layer 0, or has no object ID, THE SYSTEM SHALL show the drop-in's explanation in the selection message and in the history area, and send no save or history request.
- **AC39 (S2):** WHEN "Save inspection" is pressed with no BMP selected THE SYSTEM SHALL show the drop-in's "No BMP is selected. Click a BMP on the map first." and send no request.
- **AC18 (S2):** WHEN a save is confirmed THE SYSTEM SHALL have stored `{ "arcgis": <the feature's attributes>, "form": { "verified_campus_location", "nearby_address", "address_kind", "condition_status", "last_inspection" } }` in the inspection's snapshot, with each `form` value as shown at Save and cut to at most 500 characters (typed values via input `maxlength`, prefilled values cut before saving), and the stored snapshot at most 16384 bytes.
- **AC19 (S2):** WHEN the session is missing or expired at Save THE SYSTEM SHALL keep every form value in this tab, show "You are signed out. Sign in again in a new tab, then press Save again here." with a link to `login.html` that opens in a new tab, and save normally when "Save inspection" is pressed after that sign-in.
- **AC20 (S2):** WHEN the database (`invalid_input:<field>`) or the drop-in's own check before sending rejects a field THE SYSTEM SHALL show the drop-in's message naming that field and keep every form value.
- **AC21 (S2):** WHEN the migration in A2 is applied THE SYSTEM SHALL store `create_inspection` calls for item `5d70e438bb6045d6b3af05aee061e3cd` layer 0 from a confirmed `@umbc.edu` user and reject any other item or layer with `unknown_source` in both `create_inspection` and `my_inspections`, as verified by `supabase/tests/inspection_rules.sql`, which ends in ROLLBACK and checks row counts relative to a baseline taken at the start of its own transaction.
- **AC22 (S2):** WHEN the dashboard shows a loaded BMP list THE SYSTEM SHALL let the inspector reach "Saved at <time>" using only four controls: the BMP click (or the dropdown), the inspection type, the Pass/Fail choice and "Save inspection".
- **AC34 (S2):** WHEN the Save, sign-in or history messages change THE SYSTEM SHALL announce them through `aria-live="polite"` regions.
- **AC32 (S3):** WHEN no BMP is selected THE SYSTEM SHALL show "Select a BMP to see your past inspections." in the history area, which is a section titled "Your past inspections of this BMP" below the inspection form.
- **AC23 (S3):** WHEN a BMP is selected THE SYSTEM SHALL show "Loading…" in the history area, then that inspector's own inspections of that BMP, newest first, at most 50, each row showing date and time, inspection type and Pass/Fail.
- **AC24 (S3):** WHEN the inspector has no inspections of the selected BMP THE SYSTEM SHALL show "You have not inspected this BMP yet."
- **AC25 (S3):** WHEN loading history fails THE SYSTEM SHALL show the drop-in's error message and an empty list.
- **AC26 (S3):** WHEN the inspector opens a history row THE SYSTEM SHALL show that record's notes (or "No notes"), and the saved `form` values under the form's own field labels (or "No extra fields saved" when the record has no `form` section), using `textContent` only.
- **AC27 (S3):** WHEN the page is reloaded and the same BMP is selected again THE SYSTEM SHALL show the saved inspection, fetched from the database.
- **AC28 (S3):** WHEN a newer BMP selection happens while an older history request is pending THE SYSTEM SHALL show only the newer BMP's history.

## Open questions
- **What is the new layer's service URL?** It hasn't been read. Meanwhile the BMP is identified by portal item ID and layer ID only, and service-URL matching is removed (A1).
- **Do object IDs survive a re-import?** If `UMBC_BMP_ArcGIS_Import` is re-imported, object IDs may change, and old records would point at the wrong BMP. Meanwhile they're treated as stable for the demo. Re-check before any re-import.
